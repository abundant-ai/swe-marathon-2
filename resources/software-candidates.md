# Software candidates for SWE-Marathon 2

I would start with **EPANET for civil engineering, a SQL reporting desk for enterprise, and a 3D puzzle game with a hint companion**. In each case, a user can ask for a useful product, people can try successive builds, and a reviewer can independently check what the finished product delivers. ParaView also qualifies. Its published regression suite gives us a starting point for both workflow replay and image comparison.

The 17 proposals below include **10 with published reference outcomes**, **6 with public inputs and an independent programmatic check**, and **1 whose main quality judgment would come from simulated players**. These counts describe the proposed product scopes. A more ambitious claim about the same product may need different evidence.

| Evaluation | What goes in the private verifier |
| --- | --- |
| **Reference** | Published measurements, target artifacts, labels, expected state changes or best-known solutions. We score what the submitted application produces on held-out cases. |
| **Replay** | Public cases or fixtures plus a trusted reference program, rules engine or numerical procedure. We have to build and validate the adapter. |
| **Usage** | New play sessions from held-out user profiles. Mechanical checks can establish that the product runs. The main outcome depends on how the experience feels or serves the player. |

“Private” describes access **during the trial**. Anyone can have seen a public benchmark before. Keep expected outputs and grader code outside the developer and crowd images. For the release, add fresh variants that preserve the reference answer or recompute it independently. Split by part family, database, scene or event, as appropriate. Reserve separate cases and profiles for development pilots and final evaluation.

## Suggested first eight

**Orange, BIRD reporting, EPANET, FreeCAD, ParaView, the 3D warehouse puzzler, broadcast audio QC and the adaptive exploration game.** Five have published reference outcomes, two use an independent replay, and one relies mainly on simulated use. Orange is already in development. The seven additions would exercise distinct interfaces and deliverables, from an editable solid and a scientific visualization to corrected audio and a playable game.

The scope is one complete, reusable workflow per product. Before accepting an idea as a task, run one known-good artifact and one plausible faulty artifact through its proposed grader. Examples include a CAD file that looks right until a hole spacing changes, a report with stale SQL results, and a game hint that strands the player. This is a source-backed shortlist. Product implementations, score calibration and per-asset redistribution rights still need validation before release.
