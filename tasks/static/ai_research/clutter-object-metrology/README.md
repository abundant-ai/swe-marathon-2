# Fine object geometry in two cluttered workspaces

[Oddish experiment and trial status](https://www.oddish.app/experiments/733d7557)

An engineer needs an editable metric mesh of three small objects among other items on a real desk. Six calibrated handheld RGB keyframes show parallax, occlusions, and changes in viewpoint. The agent writes and tests a Python scene program. Its geometry must place each object accurately enough that independently rendered views agree with its visible contour and measured surface depth. The underlying Kinect recordings come from the TUM RGB-D Benchmark. [Source dataset, paper and CC BY 4.0 terms](https://cvg.cit.tum.de/data/datasets/rgbd-dataset)

## What the agent receives

| Scene | The three target objects |
|---|---|
| Freiburg 1 desk close-up | Black game controller, red square housing with a blue disc, upright white printed carton |
| Freiburg 2 desk | Gray tape roll, white handled mug, beige telephone and handset |

The written brief is identical in three observation conditions. It lists both possible acquisition tracks and target lists. The first condition receives six RGB images from the first recording on a single chronological sheet. The swapped condition receives the corresponding sheet from the other recording. A third condition receives no sheet. Private camera poses, depth and object outlines at withheld times remain outside the public environment. [Candidate brief](instruction.md)

The submitted module returns vertices in meters in the first camera's optical frame, at most 20,000 triangles, vertex colors, and one object ID per face. All visible parts and the surrounding environment share a z-buffer. For example, the tape's inner rim belongs to the tape while a patch of tabletop seen through its opening belongs to the environment. The agent can run a public smoke test, read its tracebacks, and repair its source before submission.

## What the hosted verifier measures

The agent environment transfers the final source and public test receipt. A separately built verifier executes the candidate source with reduced OS privileges, checks its mesh contract, and renders the same frozen mesh against both possible scenes. The receipt provides corroborating source-hash evidence. Geometry determines the task reward.

The primary score is surface F1 within 3 cm. Per object, count measured target pixels, predicted target pixels on measured rays, and correctly labeled intersections with depth error at most 3 cm. Pool those counts over four withheld views. Object F1 is twice the number of correct pixels divided by the sum of measured and predicted pixels. Average the three object F1 values equally. The canonical target is A for the correct and blind bundles and B for the swapped bundle. The full verifier report preserves both counterfactual scores. It also measures silhouette IoU, one-grid-pixel boundary F1, surface depth without object labels, and local normal agreement. [Frozen metric implementation](https://www.oddish.app/tasks/swe-m2_ai-research_clutter-object-metrology-swapped-c9e4647d?version=swe-m2_ai-research_clutter-object-metrology-swapped-c9e4647d-v1&drawer=task&taskFile=tests%2Fprivate%2Fprecision-pilot%2Fgeometry_eval.py)

## Design evidence

| Dimension | Evidence and remaining uncertainty |
|---|---|
| Novelty | The earlier six-keyframe pilot scored all visible depth within 20 cm. Here a model has to identify three instances, resolve their outlines under occlusion, and place small surfaces within 3 cm. A correctly placed desktop contributes little to the joint metric. The TUM dataset's published benchmark evaluates camera tracking. Here measured poses are provided, and an executable labeled scene is the deliverable. Broader novelty relative to all third-party coding tasks remains unverified. |
| Verifiability | Held-out sensor depth and visible masks provide per-object measurements independent of candidate code. Three-view transfer of independently measured, labeled depth achieved 0.902 and 0.780. A second blind trace of one withheld frame per recording agreed with the primary annotation at 0.924 and 0.869 silhouette IoU. Dark, thin or partially occluded features have greater uncertainty. |
| Realism | The input consists of real cluttered RGB videos, camera estimates, a metric coordinate system and named physical objects. That supports reconstruction review and measurement of visible geometry. Reading six stills in a contact sheet and returning one compact piece of scene code are pilot choices. Cameras with different intrinsics, other environments, and permanently hidden surfaces would need further evidence. |
| Difficulty | Small depth errors and label swaps can retain plausible appearance while removing surface F1 credit. Moving all otherwise perfect surfaces 6 cm loses all primary credit. A shift of 16 native RGB pixels lowers boundary F1 to 0.271 and 0.311. The original larger-scale reconstruction score does not establish this task's model difficulty. Compare independent model trials on the same fresh inputs. |
| Initial feasibility | A solver can identify image landmarks across views, triangulate them with the published tracks, fit shape components, and check its mesh locally. The separate sensor-assisted reference demonstrates numerical feasibility and artifact transfer; it uses privileged depth and manual input labels. The resulting 0.901 and 0.810 rewards are the measured reference values. An RGB-only agent must recover geometry from weaker evidence. |

ETH3D's multi-view stereo track also measures geometric accuracy and completeness at metric tolerances. Here a surface intersection earns credit only when the agent assigns the correct object and places it at the measured depth on the same camera ray. ScanNet++ evaluates novel images from held-out poses and supports semantic scene understanding. This pilot checks three named instances in a scene program and repeats the coding task with the input recording changed or removed. In this repository the fixed-lag camera-recalibration task also uses image evidence, but asks for a camera-to-body transform and localization covariance. Its tracked landmarks do not establish whether the agent reconstructed the surfaces of individual objects. [ETH3D multi-view scoring](https://eth3d.ethz.ch/high_res_multi_view) · [ScanNet++ tasks](https://scannetpp.mlsg.cit.tum.de/scannetpp/benchmark/docs) · [Fixed-lag camera recalibration](../../robotics/fixed-lag-fusion/steps/09-recalibrate-camera-mounts/instruction.md)

The reward gives no direct evidence about the back sides of objects never seen by the camera, watertightness, photometric accuracy, or metric accuracy outside annotated instances. The angular diagnostic uses only pixels with sufficient same-object neighborhood support. Two source clips and one duplicated annotation frame per clip limit generalization. Hosted trials can establish what happened on these particular observations.

## Reproduce the frozen telephone-desk task

The runtime tree beside this file implements the telephone-desk condition. The authoring copy follows repository formatting. A fresh checkout needs the public RGB sheet, frozen reference mesh and nine private verifier files before building the benchmark. Run the following from the task directory with the usual Oddish credentials. An existing version-1 bundle can also supply those files through `--bundle /path/to/bundle`. ## Hackability assessment

The reference and all nine GPT trials rebuilt a frozen mesh in the separate verifier. Public execution receipts matched archived final source hashes and the logs of executed smoke tests. The receipt is a declarative file in a candidate-writable directory. It can corroborate a trajectory, and cannot independently establish that the agent inspected the image. The measured geometry determines the reward.

The grader denies the reduced-privilege build process access to the test directory and reward directory and reads regular artifacts with a size limit. The input comes from a public recording. An agent with memorized geometry or outside access to the original depth could reproduce the reference using knowledge unavailable from the six views. The candidate network is disabled during the run. The benchmark covers two recordings, and rewards on them provide limited evidence of generalization to unfamiliar rooms. The residual rating is **yellow / medium**. Direct OS isolation under more demanding workloads remains unassessed.

The review found that object F1 leaves room to omit most of the surrounding scene or assign arbitrary colors. The full-video successor therefore measures whole-scene color and depth as well as object geometry. The original task's 45-minute limit and trial evidence do not demonstrate the collection's five-day workload. Its verifier also lacks the repository's typed requirement-check interface. The reference uses privileged sensor measurements. The report identified risks from unbounded expanded worker output, residual processes, and ambiguity between candidate and infrastructure errors. This version is retained as a short empirical pilot.
