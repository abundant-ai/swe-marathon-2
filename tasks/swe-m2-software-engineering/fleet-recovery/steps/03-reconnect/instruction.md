# Recover the coordinator after lost telemetry and restart

Keep the earlier behavior after a coordinator restart. A robot can accept an advance while we lose its reply and then stop inside a passage. The next coordinator process must recover which robots could still be there before issuing another command. Other areas should remain usable during recovery.

Persist the site-relative active state, including queued and assigned jobs, closures, last accepted telemetry, outstanding commands, and command identities. Use the supplied `--state` directory. The process can be killed between any two responses and restarted with the same site and state directory. The transport may retransmit an old event with identical fields and ID, including the tick that first issued a move. Only retransmissions may carry a tick earlier than the current time. Return exactly the response from that event, with the original IDs and payloads, and apply its effects once. A robot executes a command ID at most once. A visible reply must be recoverable before it is returned.

Telemetry can be duplicated or arrive out of order. Ignore sequences at or below the last accepted sequence for that robot. An offline report or an online report with null `node` means the robot's position is unconfirmed. Its prior occupation and all outstanding movement claims remain exclusive regardless of elapsed time. A node observation that lacks the matching `settled` ID cannot remove an outstanding movement claim. A fresh matching settlement at the destination confirms arrival. A fresh matching settlement at the source confirms the robot has stopped back at the source. Other locations cannot settle a command. A robot can go offline and return with fresh telemetry. Resume available work after a matching settlement clears the passage.

Accept `cancel` events with `job`. A queued job can be canceled immediately. An assigned job can be canceled before pickup while it has no outstanding pickup action. If it has an outstanding move, retain that movement claim until settlement and issue no further commands for the canceled job. Ignore cancellation of an unknown, completed, or already picked-up job, including while its pickup is outstanding. The task's state and the robot's physical movement have independent lifetimes.
