# Replay pinned recordings to live ROS 2 subscribers

A field reader needs the sealed recording service to publish native messages that downstream ROS 2 nodes can consume. A client should be able to seek on its original generation, reconnect after a service restart, and inspect accepted delivery receipts independently of the worker's standard output. Use ROS 2 Jazzy and the local DDS transport. Keep the earlier commands working, including `serve attach` for SQLite and MCAP recording splits.

```bash
python3 -m bag_conformance live --state STATE
python3 -m bag_conformance receipt --state STATE --request-id REQUEST_ID
```

Run one live worker per service directory. It reads one JSON request per line from standard input and flushes one JSON response per line. The receipt command prints the committed response for that ID, or `null` if the request has not been accepted. It can run while the worker is running. The state starts with previously sealed recordings and may concurrently receive new `serve attach` requests. Use `/app/examples/live_example.py` as a runnable client example.

## Durable requests

Each durable request has a unique nonempty `request_id`. Commit its logical effect and full response before trying to publish the reply. An identical request retry returns exactly that committed response. This includes retries after reconnecting to a new worker. A changed request under an accepted ID, an unknown reader or batch, and malformed fields produce `{"error": string}` without changing accepted state. Receipt lookup has no DDS side effects.

- `open` gives a new nonempty `reader` of at most 32 UTF-8 bytes, `generation` (positive integer or null for current), `topics` (nonempty distinct absolute ROS topic names), and a half-open `begin_ns` and `end_ns`. Selected topics must have exactly one installed ROS message type in that pinned generation. Return `{reader,generation,epoch,prefix}`, with integer `epoch` initially zero and a unique fully qualified ROS namespace in `prefix`.
- `seek` gives an existing `reader` and new `begin_ns` and `end_ns`. Keep the reader's original generation and topic selection. Advance its epoch by one, abandon the previous seek's pending delivery and retire its writers. Return `{reader,generation,epoch,prefix}` with a new namespace. An exact retry of a prior seek returns its original response without rolling back the latest seek.
- `prepare` gives `reader`, `max_events`, and `max_bytes`, with the original service bounds. Queue the transient-local prelude at the cut and then the ordered events inside the range. For this operation traverse **all** archived topics. This lets an unselected event mark the start of a new publisher boot. Apply the event and decoded byte budgets to this complete traversal, including unselected events. If the first outstanding payload exceeds its budget, return an error. Return `{reader,generation,epoch,prefix,batch,done,scanned,events}`. `scanned` counts both selected and unselected events in the prepared batch. `events` contains only selected events, with the original `poll` metadata fields except `cdr_b64`. With nothing left, return `done: true`, null `batch`, zero `scanned`, and an empty array. Otherwise return `done: false` and a pending batch ID even if all traversed events were unselected. Re-prepare a pending batch unchanged, even when the valid budgets change. Preparing does not publish any DDS messages.
- `ack` gives `reader`, `epoch`, and the current pending `batch`. Commit progress from that batch and update the acknowledged transient-local snapshot for that seek. Return `{reader,epoch,batch,acknowledged:true}`. The client should acknowledge only once it has consumed the intended DDS messages. An acknowledgement does not publish messages.

## Emit over ROS 2

`emit` takes `reader`, `epoch`, a current pending `batch`, and optional `wait_for_subscribers`, a distinct list of selected source topic names present in the batch. It is a physical attempt and has no durable ID. When supplied, allow up to three seconds in total for matching subscribers on those writers before publishing their samples. Return `{reader,epoch,batch,published}` with the count sent on selected topics. A failed or interrupted attempt can have sent a prefix. A repeated attempt can send the same bytes again until acknowledged. An acknowledged or superseded batch cannot be emitted. DDS delivery across distinct writers is asynchronous.

Publish the unchanged original CDR for a selected source topic at `prefix + source_topic` using its actual ROS type. For example, `/tf_static` contains native `tf2_msgs/msg/TFMessage`. Use reliable volatile writers for ordinary recordings and reliable transient-local depth-one writers for recorded latched topics. Keep separate writers for independent source streams. Retain the latest record per live stream and latched topic. When an event starts a new boot, retire the preceding boot's writers before handling that event even if the topic was unselected. A late subscriber must never inherit old writers after a seek or a boot change. Duplicate physical messages are permitted when a client explicitly emits an unacknowledged batch again.

After worker restart, recreate only the acknowledged transient-local state for each active seek. Do not republish acknowledged volatile messages. Retain pending batch identity so a client can recover its receipt and try an emission itself. Reopened subscriptions to different readers and seeks must remain isolated even while another requester attaches new recordings. Use the native transport, immutable index, and a clear separation between accepted commands and physical publish attempts.
