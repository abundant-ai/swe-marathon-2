# Restore a drive after the native Controller Manager is killed

Extend `/app/control_recovery/native/fenced_drive`. A drive's generation is its hardware boot epoch. The arm and a separate machine branch keep their physical positions when the arm's Controller Manager is killed. On restart the I/O bridge can briefly publish coherent, recently stamped, healthy-looking records from a retired drive epoch. The replacement manager uses the same namespace and service names, and the recovery client may have been killed too. Your code must keep the arm disarmed until there is current evidence of ownership and recover while the separate machine branch continues moving.

The existing Jazzy package, native controller services, state topic, shared-memory protocol and protected joint behavior from checkpoint 6 still apply. Keep the package and executable names and the stage 6 behavior when the new persistence parameters are absent.

## Drive fence

Support optional hardware parameter `generation_file` in the `FencedSystem` URDF. It specifies an absolute path in a pre-created writable private directory and is dedicated to one drive. The file may be missing on first boot. Restart reuses the same file. Store format is yours. Preserve a durable nondecreasing generation floor, including a coherent current generation observed while `drive_healthy` is false. Expose a newly observed floor on the state interfaces and allow it to authorize a new claim only after its update survives a process kill. A record with a generation below the restored floor makes the drive unhealthy and provides no authority, even if the record has finite values and a recent monotonic timestamp. Reject native strict mode activation against it and continue publishing inhibited command records. A healthy record at the restored floor is eligible on fresh readback. Zero provides no authority. A new manager begins without a command claim.

The update loop runs at 100 Hz. Keep filesystem reads and commits out of hardware `read`, `write`, and the realtime part of switching. An incomplete persistence operation or untrustworthy persisted record cannot authorize a motion command. The verifier kills processes with SIGKILL and does not run shutdown handlers.

## Recovery client

Support optional string ROS parameter `generation_journal` on installed `recover_drive`, with an independent private file path and the same first-boot and restart rules. The client must keep its own durable high-water mark from well-formed positive published generations, including healthy-false observations before any current-generation acquisition. A lower generation cannot authorize a native switch. The replacement client may use a different preferred controller and the same protected joint. Use fresh joint telemetry, current `list_controllers` and `list_hardware_interfaces` service readbacks and a strict native switch. Release obsolete owned claims as needed. An accepted switch needs reconciliation against current native ownership and epoch before relying on it. Keep unrelated controllers out of the switch.

The hardware and client files protect distinct layers. The drive must deny a retired claim even from a direct Jazzy strict service call. The client must defend its own restart even when the hardware file is absent and the replacement hardware component reports a healthy old generation. Keep the arm unclaimed and inhibit enabled writes while either layer sees retired input. Restore the configured controller when a healthy record matching the durable floor arrives, so a current-generation effort command moves the joint. Leave a second Controller Manager and its active actuator operating throughout the takeover.

The existing local starter and native APIs are described in `/app/examples/README.md`. Extend the stage 6 package in place, with any new source, scripts, or package installation rules under the existing `fenced_drive` package. Submit implementation files only.
